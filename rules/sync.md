# Sync Rule — 当前对话进度同步

> `/sync` 的执行规则。目标是把当前对话已经形成的项目进展沉淀到项目三件套，而不是保存聊天原文。

## 前提

- 当前会话已通过 `/project <项目名>` 接入项目
- 目标文件为 `work/<活跃项目>/AI-BRIEF.md`、`LOG.md`、`BACKLOG.md`
- 未接入项目时按 `commands.md` 的项目生产类前提报错

## 执行

1. 先读项目三件套，再检查当前对话；优先处理上次成功 `/sync` 之后的内容，边界不明时检查整段当前对话并靠去重避免重复写入。
2. 只提取已经确认的进展，按下表落地：

| 对话内容 | 目标文档 | 动作 |
|---|---|---|
| 决策、发现、验证结果、否决、回滚 | `LOG.md` | 按文件既有格式加时间戳追加 |
| 新待办、进行中变化、已完成事项 | `BACKLOG.md` | 新增、移动或勾选对应条目 |
| 阶段、当前焦点、长期约束或项目定位变化 | `AI-BRIEF.md` | 仅更新受影响章节 |

3. 写入前与现有内容去重；同一进展已有记录时更新状态，不重复追加。
4. 完成后报告改了哪些文件、同步了哪些进展；没有可落地增量时明确报告“无新增进展”。

## 边界

- 不复制聊天原文，不记录寒暄、发散讨论、未拍板方案或模型的过程性猜测
- 不为了显得有进展而改写未变化的文档
- 保留用户原有内容和项目文档既有结构
- `AI-BRIEF.md` 只保留跨会话仍有用的信息；细节留在 `LOG.md`
