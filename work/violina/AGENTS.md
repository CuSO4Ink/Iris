# Violina agent instructions

These instructions apply to work performed within `work/violina/`.

## Violina 固定小说生产

本节适用于 `work/violina/literature/novels/` 下固定小说的创建、续写、正文重写与生成实验。只读解释、规范分析或状态汇报不强制调用子代理。

### 项目目标

固定小说默认由纯 AI 生成。目标不是伪造真实人类作者经历，而是在守住事实、人物、视角与女性主受—全女性攻方关系硬边界的前提下，使匿名读者判断“更像 AI 生成”的概率稳定低于 50%，并通过跨文本回归测试继续压低。

每部作品须在 Canon 中冻结为一对一或一受多攻：主受始终为女性，攻方为一名或多名女性；男性可以作为非恋爱配角存在，但不得进入核心爱情、性、攻受或竞争位置。一受多攻不是可随时扩容的可替换后宫；攻方人数与成员由作品 Canon 固定，变更须先取得用户明确授权，各核心女性仍须保有不可互换的欲望、边界、生活线与后果。

作者来源判断是读者感知，不是真实来源鉴定。不得用“AI 写的所以不可能通过”循环论证，也不得把 HumanDraft、人类持续共写或人类来源感设为正式正文的必要条件。用户文本可以作为可选素材或共同创作输入，但不是默认起点。

### 三层闸门

1. **有效性硬闸门**：隔离审校检查事实、连续性、视角与认知、人物主体性、空间时流、硬边界、输出完整性、接口泄漏和语义退化。只有这些问题足以拒绝候选。
2. **来源风险画像**：同一审校可以报告素材巡检、等密度小单元、理想他者、感官意义化、时间尺度饱和和整齐收束，但这些只预测盲测风险，不单独阻止候选进入来源盲测。
3. **零上下文来源盲测**：有效候选以 5 个相互隔离、看不到项目与审校术语的读者为目标。当前基础通过线为 AI 概率中位数 `< 50%`，且多数读者判为“更像人写”。正式登记的试验可先冻结 3 份回答；只有五人失败已经数学锁死时才停止后两名，且不得伪造完整样本统计。报告同时保留均值、分布、最早形成判断的位置、反证与分歧。

内审不得替盲测回答“像不像 AI”。像 AI 的风险很高仍可送测；只有实际盲测结果决定来源目标是否通过。

### 正式生产路径

- **当前最佳 Writer SOP**：`work/violina/literature/novels/trials/current-best/WRITER-SOP.md` 是正式正文唯一写作基准；`CURRENT-WRITER-SYSTEM.md` 是它冻结的单一运行时写作规范。当前版本采用 Epoch 25 便携冷启动中 Human `9/9` 的原稿生成路径；审校、来源盲测和失败实验不属于写手规范。
- **根代理**：唯一统筹者、权威上下文持有者和正式文件写入者。它维护 Canon、CommittedEvents、CurrentState、长期压力与认知边界。
- **隔离写手**：根代理逐字发送当前版本 `CURRENT-WRITER-SYSTEM.md` 的标记正文，再附写手自己的一份 Concrete Frame 与输出边界。写手不搜索工作区，不读取完整 Skill、长篇后台、其他阶段 Frame、文学守门、研究登记、盲测提示或审校结论，直接一次生成 CandidateProse。
- **隔离审校员**：只读取白名单事实、必要近期正文、CandidateProse 与 `prose-generation-guard.md`；只输出硬闸门结论和非阻断风险画像，不改正文、不写文件。任何修订器都必须作为另行预登记的研究拓扑运行，不属于当前正式路径。
- **盲测读者**：只看匿名正文与来源判读问题，不接触项目后台、模型信息、生成提示或内审报告。

默认顺序：

1. 根代理从权威历史形成 Concrete Frame：`ConcreteMustHold`、`ConcreteLiveState`、`ConcreteOpenPressure`、`RecentWindow` 与 `VoiceBoundary`。不得预写 EventRecord、逐段节拍、成熟心理诊断、道具用途、必须对白、关系回报、结尾、完整人格／伦理卡、成组拒绝项或他者行为白名单。
2. 以 `fork_turns: "none"` 启动隔离写手，只发送“CurrentWriterSystem—FrozenConcreteFrame—OutputBoundary”，一次生成纯 AI CandidateProse。候选不是历史。
3. 候选完成后串行启动隔离审校。硬闸门拒绝则停止该候选并回查事实包或生成架构；硬闸门通过后冻结原稿进入来源盲测，不由审校员改写。
4. 盲测未过 `< 50%` 时，正式候选停止并汇总重复证据。只有用户授权研究时，才在 `trials/experiments/` 从当前 Writer SOP 分叉一个预登记、可完整撤销的差异；不得在正式作品内临场叠加失败架构或把审校清单逐句塞回写手上下文。
5. 盲测通过且用户接受版本后，根代理从实际正文抽取 EventRecord 与 StateDelta，按“追加事件—刷新状态—更新读者 TXT”提交。

同一候选的生成、内审、盲测与提交必须串行。不同候选或不同作品可以并行，但不得共享候选正文写入权。所有正式文件始终只由根代理写入。

### 架构迭代与收敛

开始新一轮实质性实验前，完整读取 `trials/current-best/WRITER-SOP.md`、`trials/self-iteration-protocol.md` 与 `trials/research-registry.md`，登记最相近旧实验、真正新增量、反证、候选固定方式和评价指标。完整旧散件只在历史争议或严格复现时从冷归档解压，不进入日常上下文。

允许探索的变量包括模型族与训练目标、上下文切片、Concrete Frame 结构、计划可见性、候选池与选择器、生成/修订拓扑、解码和多读者评价。提示同义改写、随机添废话、故意犯错、机械乱序或删掉漂亮句子不算实质性架构。

实验默认以至少两个不同文本截面做回归；只有盲测中位数、均值或多数判断出现可复现改善，才把变量视为有效。连续三次没有改善只说明当前支路达到经验平台，不得上升为纯 AI 目标不可能。

当前 `CurrentWriterSystem` 与 Concrete Frame 规范在一个实验内不可自修改。失败轮次只更新研究登记；只有跨文本确认并经用户批准，才生成新的 Writer SOP 版本。文学评价上升不能覆盖来源指标恶化，也不能成为保留失败差异的理由。

`fork_turns: "none"` 只隔离对话上下文，各代理仍共享工作区。子代理任务必须写明白名单路径和读写边界；写手与审校员均不得自行搜索项目。

### 历史复现边界

Epoch 02 及后续旧实验已经停止，不属于正式写作入口。完整旧协议、冻结提示、候选、回答和便携运行保存在 `trials/archive/trials-pre-restructure-2026-08-06.zip`。严格复现时必须在独立临时目录使用归档中的原始文件与关系边界；不得用当前 Writer SOP 改写历史条件，也不得把归档差异带回正式生产。
