# Reader Testing Protocol

## Purpose

测试框架关注读者结果：是否愿意继续、人物是否留下区分、情绪是否抵达、关系是否形成牵引、何处困惑或跳读，以及读者认为文本更像人类创作还是 AI 生成。它不向盲测读者解释作者采用了什么方法。

Violina 当前默认主目标是消除 AI 写作感。因此没有另行声明时，使用 `authorship-reader-prompt.md`：不要求复述情节或泛评人物，只收集作者来源判断、形成判断的位置、具体文本证据、反证、全局分布与最高杠杆问题。

## Roles

### Test Owner

- 决定本轮真正想知道的问题、读者类型、成功条件与版本映射。
- 可以接触写作规范和作品后台。
- 不直接改写盲测读者的原始回答。

### Test Builder

- 匿名化材料、生成测试包、随机化顺序并检查泄漏。
- 可以由已经了解 Violina 的 AI 承担。
- 不担任本轮盲测读者。

### Blind Reader

- 使用没有 Violina 上下文的全新 AI 任务。
- 只能看到自包含测试包，不打开工作区、不搜索背景、不推测测试目标。
- 先完成自由阅读反应，再回答结构化问题。

### Analyst

- 冻结全部原始响应后再汇总。
- 区分重复观察、个体偏好、事实误读与分析推断。
- 可以知道测试假设，但报告必须保留反例和分歧。

## Test Types

- **Smoke**：单个开篇或场景，验证能否进入、能否理解、是否愿意继续。
- **Regression**：同一材料修改前后匿名 A/B，对比读者结果是否改善。
- **Continuity**：连续多章阅读，检查记忆、关系积累、情绪余震与阅读疲劳。
- **Storefront**：只测试书名、文案、标签和开篇承诺是否匹配。
- **Targeted**：针对某类读者或某个具体阅读问题；假设只写在 manifest，不进入 packet。
- **Authorship Perception**：集中测试文本给人的作者来源印象；必须在自由阅读反应之后询问，记录判断、置信度、证据与反证。

Authorship Perception 的有效回答至少包含：

- 未分析前的第一判断与 AI 概率。
- AI 感首次形成或明显增强的位置。
- 最多五个最强 AI 感证据，每个证据对应具体片段与感受原因。
- 至少两个最强人写感反证。
- AI 感是全局均匀还是集中在特定段落、人物或表达类型。
- 若只能优先消除一个反复模式，应选择哪一个，以及为什么它最影响作者来源判断。

不询问与作者来源感无关的情节喜好、设定偏好或续写建议；只有当情节组织、人物表现或关系表达本身构成 AI 感证据时才记录。

## Run Lifecycle

```text
Define → Package → Leak Check → Dispatch → Collect → Freeze → Aggregate → Decide
```

1. **Define**：建立 manifest，写清唯一主问题、辅助问题、读者类型、版本与成功条件。
2. **Package**：生成匿名 packet。A/B 测试使用无含义标签并随机顺序，不使用“旧版/新版”。
3. **Leak Check**：确认包内不存在项目名、路径、版本说明、测试假设、写作术语、后台事实和作者期待。
4. **Dispatch**：每名读者使用独立全新任务；只粘贴 packet，不补充口头提示。
5. **Collect**：保存完整原始回答，不先挑选有用段落，不让读者在看见他人意见后返答。
6. **Freeze**：标记本轮收集结束；冻结后才能打开 manifest 的版本映射做分析。
7. **Aggregate**：先汇总阅读结果，再解释可能原因；共同意见与少数意见分开。
8. **Decide**：由 Test Owner 决定接受、继续验证或不采纳。未经重复证据支持，不把单次反馈升级成长期规则。

## Packet Rules

- 只包含普通读者本应看见的材料。是否提供书名、文案和标签由测试类型决定。
- 删除本地路径、提交信息、修订说明、后台标题、模型名称和生成提示。
- 不出现“噪声”“振幅”“低温同声”“周密腔”等作者侧术语。
- 问题只询问体验、记忆、判断和文本证据，不暗示正确答案。
- “人写还是 AI 写”必须放在自由反应之后；不得提前告诉读者真实来源，也不得把某种语言特征提示为标准答案。
- 若测试某个中后段场景，只提供真实读者在该位置已经知道的必要前文，不补充后台解释。

## Entry Rules

- `/project violina` 只代表工作区被激活，不能替代 reader-testing 的精确文件路径。
- 框架操作员必须从对话中的外部指令直接获得 `work/violina/literature/reader-testing/README.md` 与 `protocol.md` 的准确路径，只读明确列出的框架文件。
- 盲测读者不接入项目、不寻找 testing 目录、不读取 framework prompt；直接接收完整匿名 packet。
- “读取 reader testing 部分”不是有效接入指令，因为它既没有给出准确路径，也混淆了操作员与盲测读者角色。

## Minimum Sample

- Smoke：至少 3 个相互隔离的读者响应。
- Regression A/B：至少 5 个相互隔离的读者响应，并随机一半的版本顺序。
- Continuity：至少 3 个完整阅读响应；中途退出也作为有效结果保存。
- Authorship Perception：至少 5 个相互隔离的读者响应；先比较作者来源判断与重复证据，再看平均分。

样本数用于减少单次模型偶然性，不用于伪装统计显著性。结论必须描述观察范围，不把少量 AI 响应写成普遍读者事实。

## Report Discipline

- 先写“读者发生了什么”，后写“可能为什么”。
- 每个重要结论至少关联具体位置或多名读者的独立复现。
- “没有提到”不等于“没有感受到”；只有主动问题后的回答才能作为相应证据。
- 读者提出的修改方案只视为症状线索，不直接当作正确修法。
- 当读者把多余、粗糙或不可预测之处视为人写证据时，分析者须区分有方向的注意与知识偏差和随机缺陷：寻找同一文本中反复偏爱的对象、持续的词域边界、局部过写与相邻遗漏；只出现一次的废话、错词或疏漏不能单独证明路径残余。此项属于分析推断，必须与读者原话分开。
- 作者来源判断只代表该读者在本次材料上的感知。报告使用“更像人写／更像 AI 写”和概率分布，不把 AI 判断写成事实鉴定。
- 报告必须列出相反证据、分歧和本轮无法回答的问题。
