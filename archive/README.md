# archive — 归档区

已结项、已否决或没有近期工作的项目。归档内容停止执行和维护，但必须仍能独立说明
项目做了什么、得到什么、凭什么得到，以及以后如何安全重启。

## 核心规则

- 归档不是摘要、备份或垃圾桶；最终状态页是入口，不能替代项目记录。
- 先在 `work/<项目>/` 收尾和分类，再把保留下来的项目目录整体移动到
  `archive/<项目>/`。不得只新建一页摘要后删除原目录。
- Git 和维护备份只用于恢复，不是删除当前可查阅记录的理由。
- 无法确认价值或唯一性的内容默认保留；先证明可删，再删除。

## 进入条件

- 项目已结项、明确否决，或没有可执行的近期计划。
- `AI-BRIEF.md` 状态改为 `archived`，并写明归档日期、原因、最终结果、已知限制、
  后续方案或重启条件。
- 不再保留“待继续执行”的活动态任务。未完成但不再计划执行的事项，收敛成最终限制、
  否决结论或重启条件。

## 保留与删除

| 内容 | 处理 |
|---|---|
| `AI-BRIEF.md` | 必须保留，作为最终状态和文档地图入口 |
| `LOG.md` | 保留耐久决策、否决、发现和回滚；不得因归档清空 |
| 规范、研究报告、交付文档 | 能解释最终结果、限制或复用方法时保留 |
| 源码、配置、补丁、许可证 | 最终结果或复现所需时保留；外部真值须记录位置和版本 |
| 最终证据 | 被 Brief 的结论直接引用时保留 |
| `BACKLOG.md` | 已无可执行任务时删除；含唯一重启条件时改为非执行态 `RESTART-NOTES.md` |
| 环境、缓存、构建产物、下载依赖 | 可重建且无唯一内容时删除 |
| 运行目录、原始截图、重复导出、一次性脚本 | 未晋升为最终证据或耐久源码时删除 |
| 重复草稿、已替代副本 | 正式结果存在、有效引用已更新且无唯一内容时删除 |

删除候选必须同时满足：

1. 不影响理解、验证、复现或复用最终结果；
2. 已存在明确的正式结果、替代路径或可验证的重建方式；
3. 不含未提交、未跟踪、外部或用户所有的唯一数据。

失败实验只有在形成可复用的否决结论、边界或回滚点时保留；命令流水和重复运行数据不保留。

## 执行流程

1. 盘点当前文件、Git 中已跟踪文件、未跟踪文件、忽略文件和外部资产。
2. 在 Brief 写最终状态、结论边界、正式结果位置和重启条件。
3. 逐个顶层目录和大文件判断“保留 / 删除 / 原因 / 恢复来源”；清单可放在 `tmp/`
   作为本次操作证据，不为每个项目新增长期清单。
4. 只删除满足上述三个条件的候选；结构性文件按维护规则先备份。
5. 将剩余目录整体从 `work/<项目>/` 移到 `archive/<项目>/`，更新有效引用。
6. 校验文件数量、关键文件、内部链接和 Git 差异，并报告实际删除项及恢复方式。

归档操作不自动提交、推送或清理无关脏改动。

## 不放什么

- 还在维护或有明确近期计划的项目留在 `work/`。
- 被替换的规则、入口、兼容层和备用流程在更新有效引用后直接删除，历史由 Git 保存。
- 单纯过时的长期笔记在 `notes/` 原地更新或删除，不作为项目归档。

## 取回

将目录从 `archive/` 整体移回 `work/`，删除 Brief 的归档说明，建立新的执行合同；
UE 项目恢复 live 工作时重新执行 UEAgent gate。
