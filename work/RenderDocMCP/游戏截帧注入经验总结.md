# 游戏截帧注入经验总结 —— 以 TLOU2 (Streamline/NVAPI) 为例

> 面向需要对商业/研发构建游戏做 RenderDoc 截帧、但遇到「注入不生效」或「注入即崩溃」的人。
> 从一次 The Last of Us Part II 的完整排查中提炼，去掉排查流水，只留可复用的判断链、根因和操作方法。
> 案例环境：RenderDoc v1.45、TLOU2 研发构建、RTX 3080、Windows 11、NVIDIA Streamline 2.7.2。

---

## 0. 一句话结论

对使用 **NVIDIA Streamline（DLSS/Frame Generation/Reflex）** 的 D3D12 游戏，标准 RenderDoc **注入链路能打通、却抓不到帧甚至崩溃**，根因是两层兼容性问题：① RenderDoc 默认置空 NVAPI 导致游戏启动崩溃；② Streamline 自己导出 `D3D12CreateDevice`/`CreateDXGIFactory*`，绕过了 RenderDoc 只挂在 `d3d12.dll`/`dxgi.dll` 上的 Hook。**最终靠定制编译 RenderDoc 解决，不改游戏任何文件。**

---

## 1. 排查判断链（从现象到根因，逐层排除）

遇到"截不了帧"时，按这个顺序自查，能快速定位卡在哪一层。每一层都有明确的"过关判据"。

| 层级 | 现象 | 根因 | 过关判据 |
|------|------|------|----------|
| **L0 启动方式** | RenderDoc GUI Launch 弹出的是启动器而非游戏本体 | 工作目录不对，游戏找不到相对路径资源，回退启动器逻辑 | 命令行 `capture --working-dir <游戏目录>`，游戏本体直接起来 |
| **L1 进程二次拉起** | 工作目录对了，但 RenderDoc 追踪页一闪而过、最终进程没加载 `renderdoc.dll` | 父进程注入后立即拉起子进程并自己退出，子进程没被注入 | 加 `--opt-hook-children`，日志出现对子进程的 `Injecting renderdoc into process ...` |
| **L2 图形 API 挂钩时机** | DLL 注入成功、控制端口在监听、GUI 能连上，**但无 Overlay、F12 无反应** | 对**已运行**进程注入时，D3D12 Device/SwapChain 已创建完毕，RenderDoc 错过了图形 API 初始化时机 | 必须在**进程创建阶段**注入（用 `capture` 而非 `inject`） |
| **L3 NVAPI 兼容** | Hook 成功、抓到 `New D3D12 device created`，但游戏随即崩溃 `0xC0000005` | RenderDoc 默认禁用 NVAPI，返回 NULL；游戏未处理初始化失败而崩溃 | 目标进程内放行 NVIDIA Vendor Extensions，日志由 `NvAPI disabled` 变为 `NvAPI allowed` |
| **L4 Interposer 旁路** | NVAPI 放行后游戏能进，但只出现短命探测设备、无 SwapChain/Present、仍无 Overlay | 真正的 Device/Factory/SwapChain 由 `sl.interposer.dll` 创建，绕过了 RenderDoc 只挂系统 dll 的 Hook | 额外 Hook Streamline 导出的 `D3D12CreateDevice`/`CreateDXGIFactory*`，日志出现 `wrapping sl.interposer D3D12CreateDevice` |

> **核心心智**：**"DLL 注入成功 + 控制连接成功" ≠ "图形 API 被挂钩"。** 这是最容易被假成功骗到的一层——端口在听、GUI 显示连上了，很像成了，但 Overlay 和 F12 才是真正的挂钩证据。

---

## 2. 两条关键坑（最值得记住）

### 坑一：对运行中进程 `inject` 对这类游戏无效
游戏的 D3D12 设备在你注入之前早就建好了，RenderDoc 挂不上已经创建的 Device。**必须用 `capture` 从进程创建阶段注入**，`inject` 只适合那些启动后才延迟建图形设备的程序。

### 坑二：Streamline / DLSS 游戏会双重绕过 RenderDoc
1. **启动崩溃**：RenderDoc 默认不放行 Unsupported NVIDIA Vendor Extensions，把 `NvAPI_EnumPhysicalGPUs`、`NvAPI_SYS_GetDriverAndBranchVersion`、`NvAPI_DRS_*` 等一律返回 NULL。游戏没做失败处理，稳定崩在固定偏移（本例 `tlou-ii.exe+0x1291B99`，`movsxd rax,[rbx+8]` 读空指针）。
2. **抓不到帧**：即便放行 NVAPI，`sl.interposer.dll` 自己导出了 `D3D12CreateDevice` 和 `CreateDXGIFactory/1/2`，真正的渲染设备走 Interposer 创建，而原版 RenderDoc 只 Hook 系统 `d3d12.dll`/`dxgi.dll`，于是完全被旁路。

---

## 3. 已验证无效的方向（省下别人重走弯路的时间）

以下都**不能**解决 Streamline 游戏的启动崩溃，别浪费时间：

- 关闭 NVIDIA In-Game Overlay
- 换 RenderDoc 版本（v1.43 / v1.45 Release 都试过）
- 设 `NV.BlockNVAPI=false` 或 `=true`（两个方向都试过）
- 单独恢复 Shader Model 6.8 / Raytracing Tier 1.2 / Sampler Feedback Tier 0.9 中的任意一项或全部

由此反证：RenderDoc 的三项能力降级（SM 6.8→6.7、RT Tier 1.2→1.1、Sampler Feedback→NOT_SUPPORTED）**不是**崩溃根因。最终方案保留了这些默认降级行为，照样能截帧。

**同样不建议做的破坏性操作：**
- 删除/改名 `sl.interposer.dll`、`sl.common.dll` 等游戏组件（可能直接起不来）
- 改 exe 或打补丁绕过完整性校验
- 反复启动触发崩溃（只会堆一堆 crash dump）

## 4. 最终解决方案：定制编译 RenderDoc（不动游戏文件）

在 RenderDoc 源码（官方提交 `2fc0bc04`）上做三处修改，重新编译：

**① NVAPI 放行**（`renderdoc/driver/ihv/nv/nvapi_hooks.cpp`）
在 `NvAPI_Initialize_hook()` 里调用官方 `EnableVendorExtensions(VendorExtensions::NvAPI)`，放行显卡枚举/驱动信息/显示/DRS 等启动必需查询；同时对**未经 RenderDoc 正式包装**的原始 `NvAPI_D3D12_*` 接口返回 NULL，防止 NVIDIA 驱动收到无法识别的 Wrapped Device。

```cpp
if(!NV_BlockNVAPI())
  RenderDoc::Inst().EnableVendorExtensions(VendorExtensions::NvAPI);
if(cname && !strncmp(cname, "NvAPI_D3D12_", 12))
  return NULL;
```

**② Hook Streamline 的 D3D12 导出**（`renderdoc/driver/d3d12/d3d12_hooks.cpp`）
```cpp
LibraryHooks::RegisterLibraryHook("sl.interposer.dll", NULL);
StreamlineCreateDevice.Register("sl.interposer.dll", "D3D12CreateDevice",
                                Streamline_D3D12CreateDevice_hook);
```
用独立 `HookedFunction` 保存 Streamline 原函数指针，再走 RenderDoc 原有 `Create_Internal()` 包装最终 Device；递归进系统 `d3d12.dll` 时靠 TLS 重入保护避免二次包装。

**③ Hook Streamline 的 DXGI 导出**（`renderdoc/driver/dxgi/dxgi_hooks.cpp`）
Hook `CreateDXGIFactory`/`CreateDXGIFactory1`/`CreateDXGIFactory2`；调 Streamline 原函数时用 `ScopedSuppressHooking` 防双重包装，再用 `RefCountDXGIObject::HandleWrap()` 包装其返回的 Factory。

**编译**（VS Build Tools 2022 v143 + Win11 SDK，官方工程默认 v140，命令行临时指定 v143）：
```powershell
$src = 'C:\Work\AI\Iris\work\RenderDocMCP\tools\renderdoc_src_2fc0bc04\'
$msbuild = 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\MSBuild.exe'
& $msbuild "$src\renderdoccmd\renderdoccmd.vcxproj" /m:8 /nodeReuse:false `
  /p:Configuration=Development /p:Platform=x64 /p:PlatformToolset=v143 "/p:SolutionDir=$src"
```
产物：`x64\Development\renderdoccmd.exe` 和 `renderdoc.dll`。

成功日志特征（说明改动生效）：
```text
TLOU2 isolation: wrapping sl.interposer D3D12CreateDevice
Adding D3D12 frame capturer
Starting capture → Finished capture, Frame 3460 → Captured D3D12 frame
```

## 5. 日常截帧流程（方案落地后）

1. 确认游戏**已完全退出**（脚本会拒绝对已运行进程重复注入）。
2. 双击一键脚本 `启动TLOU2_RenderDoc截帧.cmd`（自动校验定制 RenderDoc 与游戏 EXE、按时间戳建独立捕获目录、设正确工作目录并注入）。
3. 在游戏启动窗口点"开始游戏"，等待进入。
4. 确认**左上角出现 RenderDoc Overlay**（这是挂钩成功的唯一可信标志）。
5. 进目标场景，**按一次 F12**，等写盘完成再退游戏。
6. 用系统安装版 RenderDoc v1.45 打开 `.rdc` 做回放分析。

手动等价命令（不需要 `--opt-hook-children`，直接抓 `tlou-ii.exe`）：
```powershell
& "...\renderdoc_src_2fc0bc04\x64\Development\renderdoccmd.exe" capture `
  --working-dir "<游戏目录>" `
  --capture-file "<捕获目录>\tlou2_capture" `
  "<游戏目录>\tlou-ii.exe"
```

---

## 6. 操作注意事项

- **截帧启动必须用定制 `renderdoccmd.exe`**；系统安装版没有 NVAPI/Streamline 兼容改动，只能用来**打开** `.rdc`。
- 不要删除或覆盖 `tools\renderdoc_src_2fc0bc04\x64\Development` 目录，一键脚本依赖其中的 EXE/DLL。
- 单帧可达 **3–4 GiB**，原始 Capture Section 可超 13 GiB。按一次 F12 后耐心等写盘（本例约 18 秒），**不要连按**。
- 打开大型 `.rdc` 前**先退出游戏**，否则游戏显存与回放资源叠加易触发 Device Lost。
- 最终方案**只改 RenderDoc、不改游戏文件**；`AllowUnsupportedVendorExtensions` 官方标记为不受支持，本补丁额外拦截未包装的原始 `NvAPI_D3D12_*`，但仅应用于本游戏的离线图形分析。

---

## 7. 把经验迁移到别的游戏

这套判断链对**任何用 Streamline / DLSS / 第三方图形 Interposer 的 D3D12 游戏**都适用。换游戏时重点确认：

1. 游戏是否经启动器二次拉起 → 决定要不要 `--opt-hook-children` 与正确 `--working-dir`。
2. 游戏目录里有没有 `sl.interposer.dll` 等 Streamline 组件 → 有则大概率需要 Hook 其导出的 `D3D12CreateDevice`/`CreateDXGIFactory*`。
3. 启动崩溃是否伴随日志里的 `NvAPI disabled ... Returning NULL` → 是则需要放行 NVAPI Vendor Extensions。
4. 判断挂钩是否真成功，**永远以 Overlay + F12 能出帧为准**，不要被"端口在听/GUI 连上"骗到。
