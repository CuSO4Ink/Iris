# Onboarding · Project — 项目接入指令（L0 + L2）

> **用法**：粘贴前把全部 `{项目名}` 替换成实际项目名。

---

```text
你接入的是 ankoha 的工作区：Iris（以仓库根目录为准）
接手项目：{项目名}，目录 work/{项目名}/

先按顺序读：
1. rules/00-canary.ankoha.md
2. 先检查 `work/{项目名}/AI-BRIEF.md` 顶部；若有 `<!-- iris-project-kind: ue -->`，只读取并执行顶部的 UEAgent-first 导航，确认路由状态后再读项目任务内容。
3. work/{项目名}/AI-BRIEF.md：先读当前状态、当前焦点、硬约束和文档地图，再按任务读取相关部分；全局规划或重构时才逐条读完
4. work/{项目名}/BACKLOG.md：先读进行中和任务相关条目；全局规划或盘点时才读完整文件

LOG.md 按需读（查历史决策时再 grep 或尾部看近期几条）。
若 AI-BRIEF.md 不存在，普通项目用 `/project-init {项目名}`，UE 项目用 `/project-init {项目名} --ue` 初始化。

硬底线：每次自然语言回复末尾单独一行输出 `唔呣。`

边界（主动提议前自检）：
- 默认改动在 work/{项目名}/；AI-BRIEF 或当前任务明确列出的项目源码、资源和测试目录也属于项目范围
- 共享规则、斜杠命令、接入模板和 vault 结构仅在用户明确纳入当前请求时修改
- 发现跨项目重复问题可报告；未获明确授权时不改共享层
- 用户明确要求框架/规则与项目联动时，按 `rules/maintainer/` 在其给定范围内直接执行，无需再次切换角色
- 遇到未注册斜杠命令：按 commands.md 协议报错即可，不主动提议登记新命令

读完回复"{项目名} 接入完成，唔呣。"
```

---

## 维护

- 入口文件路径变动 → 改方框
- 项目协作约定 → 写进各项目 `AI-BRIEF.md`，不改本模板
- 边界条款变更 → 同步检查 Onboarding-Maintainer 是否对称
